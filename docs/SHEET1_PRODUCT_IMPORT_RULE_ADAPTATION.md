# Sprint 2 Product Truth import and model improvement — 30 October 2026

## Data separation (mandatory)

**Operational MVP import** reads ONLY the `1. Kich ban goc` sheet and
requires exactly `VID_GOC01`–`VID_GOC06`. Columns A–K are retained:
video code, SKU, product name, brand, reference price in VND, variant,
expected video description, approved claims, source origin, owner, and note.

The importer accepts a workbook containing only Sheet 1, OR the original
multi-sheet workbook; extra sheets are **ignored**. It does not load 44
error videos, 30 public videos, simulated predictions, labels, test outcomes,
or legal-policy rules into operational Product Truth.

Existing SKUs are never overwritten implicitly. Import metadata (variant,
source type, expected video description) is attached separately. Conflicting
SKU core values are returned in `core_conflicts_not_overwritten`; review
these items manually. Source type 'Giả lập (ví dụ minh họa)' stays
`reference_status=unverified`, regardless of successful upload.

**Usage:** Product Truth page → Import Excel 6 sản phẩm gốc, or use
`POST /api/products/import` multipart `file`.
Downloadable single-sheet template can be generated by copying columns
A–K and six product rows from Sheet 1 into a new XLSX workbook.
Use **Xóa Excel sản phẩm gốc** only after exporting any dependent
sessions; it requires typing `XOA EXCEL`. It preserves manually edited
or already-reviewed Product Truth and rejects deletion if linked jobs exist.

Note: legacy `/api/dataset/import` remains for historical 80-case
evaluation compatibility but is **not wired to the MVP Excel upload UI**.
Do not mix historical simulated counts with measured jobs.

## How Sheet 2 informs AI

44 described controlled manipulations (8 price, 7 SKU/info, 7 claims,
7 text/subtitles, 9 visual changes, 6 AI-label omissions) are
**development examples**, not ground-truth video predictions.
Run:

```powershell
python scripts/build_sprint2_examples.py --xlsx "Sprint 2 - Thu thập & tạo dữ liệu thật (2).xlsx" --out reports/sprint2_scenario_examples.json
```

This produces structured examples with source video groups, expected
modifications and review status; it **does not fine-tune Gemini model
weights**. The Gemini prompt uses a few scenario-derived in-context
illustrations, and the rule engine implements conservative text candidates.

| Code | Basis | Trigger | Caveat |
|---|---|---|---|
| `PRICE-01` | Existing price parser | Explicit current VND price differs from reference | Discounts and ambiguity require human review |
| `SKU-01` | Existing brand rule / Gemini | Clearly observable contradicting brand label | No image-backed authentic SKU proof |
| `VARIANT-01` | Sheet 2: VID_LOI11/14 + PUB003-style scenario | Explicit mismatch in units (ml/g/tờ/size), or conflicting units in text | Can confuse separate products/variants |
| `CLAIM-02` | Sheet 2: VID_LOI16–22 | Curated high-risk phrases absent from Approved Claims | Not a general semantic claim checker or legal decision |
| `TEXT-01` | Sheet 2: VID_LOI24/28 | OCR typo close to reference brand repeated across 2 frames, OCR confidence ≥ 0.90 | Not comprehensive Vietnamese spellchecking |
| `VIS-01/02/03` | Existing Gemini/visual | Visual candidate hypotheses | VIS-02 needs `VLM_MAX_PAIRS>0`, default is 0 |
| AI disclosure | VID_LOI39–44 | **Human verification only** | Missing label in sampled frames cannot establish a disclosure violation |

New rule candidates are recorded as medium-severity findings with source,
timestamp and evidence link. The verification aggregator keeps them as
`REVIEW_REQUIRED`, not auto-rejection. Gemini's confidence values
remain uncalibrated. Model outages or unavailable OCR/ASR must remain
visible as missing coverage.

## Evaluation and anti-leakage requirements

Feeding example patterns to a model or deterministic rule and then
evaluating those **same video manipulations** is data leakage.
Do not call the 44 scenario-derived labels an independently held-out
test set. Use separate video-source groups for development vs evaluation.
Six originals with many derived clips do not yield 50 independent videos.

A future real weight-training/fine-tuning effort needs independently
adjudicated frame/OCR/ASR evidence, sufficient representative samples,
a held-out split by original source and a model/API that permits training.
The current Gemini integration is an inference API, not a fine-tuning
pipeline. No weights were updated in this change.
